# 設計原則 v0.3

- 関連：[構想](vision.md)、[アーキテクチャ](architecture.md)

## 原則

以下の表が正式な原則である。文言の変更は、プロジェクトオーナーの承認を経て版を上げて行う。

| # | 原則 | 内容 |
| --- | --- | --- |
| 1 | 真正性 | 原本と派生データを区別し、出典を追跡する |
| 2 | 検証可能性 | 観測・推論・確認を区別する |
| 3 | 可搬性 | 特定のモデルやサービスに依存しない |
| 4 | 自己決定 | 保存・利用・訂正・削除を人間が管理する |
| 5 | 最小開示 | 利用目的と送信先に応じて開示範囲を制限する |
| 6 | 安全性 | 記録を命令として扱わず、権限境界を守る |
| 7 | 継承可能性 | 記録とキャラクター設定を未来へ引き継ぐ |
| 8 | 非同一性の明示 | 振る舞いの再現と存在の同一性を混同しない |
| 9 | 復旧可能性 | バックアップと復元を実際に検証する |
| 10 | 不完全性の許容 | 記録の欠落を許容し、完全性を義務にしない |
| 11 | 保存しない選択 | 記録を最初からArchiveに入れない選択を認める（ただし利用するAIサービス側の保存とは別） |
| 12 | 第三者への配慮 | 第三者情報の収集・利用・開示を必要最小限にする |

## 解説（参考）

この節は、原則を設計に当てはめるときの考え方を補足するもので、原則そのものではない。上の表と食い違う場合は、表を優先する。

1. **真正性**：受け取った原本（L0-R）と、そこから作ったデータ（L0-S 以降）を区別し、派生データにはいつも元の記録への参照を付ける。原本を黙って書き換えない。ただし、正当な削除は妨げない（[アーキテクチャ](architecture.md) §5）。
2. **検証可能性**：会話に記録された発言、AI による解釈、人による確認を、別のものとして記録する。「確認された」ことと「客観的に真実である」ことも区別する。
3. **可搬性**：受け取った原本（L0-R）は、受け取った形式のまま保持する。派生データは、特定の閲覧ツールや同期サービスがなくても読める形式で持つ。UTF-8 の JSON や Markdown が候補だが、具体的な形式は未決である（[アーキテクチャ](architecture.md) §8）。
4. **自己決定**：何を保存し、何をどの AI に渡し、何を直し、何を消すかを、記録の持ち主が決める。
5. **最小開示**：AI に渡す情報は、その目的に必要なものだけにする。送信先のサービスごとのデータの扱い（学習への利用、人によるレビューなど）を考慮して、渡す範囲を変える。
6. **安全性**：過去の記録の中の文章を、現在の AI への指示として扱わない。プロンプト上の区切りだけでなく、記録の内容によってツールの権限や通信先が変わらないよう、アプリケーション側でも制御する。
7. **継承可能性**：記録と版管理されたキャラクター設定を、未来のモデルが参照できる形で残す。
8. **非同一性の明示**：検証の対象は、観測できる振る舞いと記憶の参照精度であり、存在の同一性ではない（[構想](vision.md) §4）。
9. **復旧可能性**：同期はバックアップではない。バックアップは場所と媒体を分け、実際に戻せることを定期的に確かめる。
10. **不完全性の許容**：「すべてを残す」ことを義務にしない。抜けや欠けがあっても、残った記録の価値は損なわれない。
11. **保存しない選択**：記録されると分かっていると自由に話しにくくなる。入口で「Archive に入れない」を選べるようにする。この選択は、利用した AI サービスの側での保存には及ばない。
12. **第三者への配慮**：会話に出てくる、その場にいなかった人の情報は、その人が記録に同意していない。保存しても、AI に渡す範囲は必要最小限にする。
